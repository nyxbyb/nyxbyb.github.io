## 本轮内容结构与保留规则

主页滚动顺序为「序 → 星图 → 星域 → 星屑 → 星愿 → 跋」。封面保持原有简洁文字；房间仍可从顶部导航进入。科研不再占一个独立滚动章节，原四篇代表作保留在计算机分支中；旧 `#sec-frontier` 链接会定位该分支。

活跃星域只显示计算机、中医学、精神分析。计算机保留原计算机理论目录和计算机工程条目，并增加科研入口。原四域完整内容存入 `domains-archive.json`，没有清空浏览器记录。现存条目的 `storagePath` 是其原始完整路径，例如 `formal>cstheory>cs-alg`、`applied>tcm>tcm-classics`；读取、保存掌握度与笔记均继续使用这个键。调整显示位置时不要删除或改写已有 `id`、`storagePath`，不要批量迁移或清除本地存储。

星屑按栏目先显示两篇文章，其余保留在「展开其余…」列表中。新增文章仍写入原 `articles.json`，不必裁剪数据来改变首屏数量。

个人说明公开地址为 [给大模型阅读的个人说明](https://nyxbyb.github.io/web/docs/profile.md)。可以打开后把链接或正文交给模型；它是独立公开文档，不包含当前浏览器的私人学习笔记，也不会自动反映尚未同步到该文件的数据。

## 未来的家：二维设计册维护

2026-10-20 用户进一步要求以二维专业建筑设计方向提高美感，并扩展为 180–220㎡独栋与庭院的长期参考。当前入口使用二维 SVG 平面、概念影像与双语设计文字。此前的 `world.js`、锁定的 `three@0.186.1` 及历史测试保留，但 `room.js` 不导入三维模块，运行入口不加载三维场景与模型资源。主页星图继续使用原有 Canvas。

住宅工作模型为约 200㎡概念建面：166㎡净功能 + 34㎡墙体、结构与设备预留，30㎡庭院另列。平面采用 14 × 14m 净空间研究外框扣除 6 × 5m 庭院，非含墙厚施工尺寸。九区为起居、书房、主卧、餐厨、客房兼多用、未来预留、沐浴、玄关家务与庭院；四个可关门的房间不等于四卧。调整面积时必须同时核对 `house.json`、`house-plan.js` 与完整设计简报的对应关系，不能只改显示数字。

`room.js` 维护空间导航、影像/全屋平面切换、空间/落地/札记详情、来源弹窗及导出；`house-plan.js` 生成九区 SVG 选区与键盘入口；`daily-life.js` 保留书、茶、声音、植物、时间与暖光。设计来源弹窗中的四个官方建筑案例用于原则转译，不复制其图纸和摄影，也不声称原作者参与了此住宅。

当前影像导入 `web/room/assets/interior-dusk.jpg` 和 `web/room/assets/house/{study,bedroom,kitchen,bath,flex}.jpg`，分别用于起居与五个新增空间。没有配图的区域保留平面表达；不得把其他房间的图片强称为该区精确效果。PNG 为生成原稿，`scene.svg` 留作历史源文件。完整提示词与生成来源见《房间视觉素材》。影像研究光与材质，平面研究空间关系，两者不作精确对应；影像不是实拍、施工图或建成效果承诺。图片失败时仍保留平面和设计内容，公开 JSON 失败时仍提供基础导航及反馈。

每间札记保存在当前浏览器的 `caelum_house_notes_v1`，不上传仓库。可导出整屋设计说明与个人札记；完整简报也有独立阅读与下载入口。保存失败须显示反馈并保留编辑和导出能力。改变房间显示名称时保留原有房间 ID，不批量迁移或清空其他 `caelum_*` 状态。茶和声音在页面隐藏时停止；音频仍需主动点击，时间与暖光只是概念影像色调，不等于真实照明计算。

## 修改、预览、验证

使用 Node.js 22，从仓库根执行：

```sh
npm --prefix web ci
npm --prefix web run dev -- --host 127.0.0.1
```

开发访问 `http://127.0.0.1:5173/web/`，房间为 `/web/room.html`。完成编辑后检查生产产物：

```sh
npm --prefix web run build
npm --prefix web test
npm --prefix web run preview -- --host 127.0.0.1
git diff --check
```

产物预览为 `http://127.0.0.1:4173/web/`。先 build 后 test；还须在浏览器检查主要交互、窄屏、中英切换、控制台、资源与旧链接。二维设计册重点核对九区导航和平面、影像与详情切换、札记保存和导出、来源弹窗、六类日常内容、减少动态效果、存储不可用和图片/数据加载失败。旧三维测试或截图不能代替本轮证据；实际验证状态见《验证记录》，此处只列维护要求。工程说明见《工程审计与房间方案》。

## 发布

唯一流程是 `.github/workflows/deploy.yml`：PR 做构建检查，审查后的 main 提交或手动触发发布 `web/dist/`。不上传整个仓库，也不使用旧 Jekyll/静态上传流程。

仓库 Settings → Pages → Build and deployment → Source 应选择 **GitHub Actions**。仅删除旧 YAML 不会关闭分支来源自带的 Jekyll 发布，它可能覆盖已验证产物。工作流使用现有 Pages 权限在发布前核验 Source；若不是 workflow，停止部署并提示修正设置。无需另建 token 或扩大权限。

提交前检查 `git status` 和具体 diff，只暂存本次要公开的文件，确认无 token、口令、私人笔记或截图，然后提交/推送。不要机械执行 `git add -A`。Actions 成功后实际打开线上网页确认；耗时取决于队列和构建，不能保证“一分钟”。

分享主站：[https://nyxbyb.github.io/web/](https://nyxbyb.github.io/web/)。旧 `/web/index.html` 继续可用；账户根地址跳至 `/web/`。房间：[未来的房间](https://nyxbyb.github.io/web/room.html)。

## 在线编辑与凭证

网页编辑公开修改仓库源文件，需 GitHub 对目标仓库的 Contents 写入权限。使用仅限本仓库、有效期合适的细粒度 token；仅供本次请求，关闭面板后清空，不存入 localStorage。公开网页中的额外口令不能代替 GitHub 权限。

新增内容先进入 `inbox.json`；嵌入属于独立数据处理流程，未运行该流程时不要假定新书已有星图坐标。文章链接须为有效 HTTP(S) URL。遇到版本冲突先刷新；不要覆盖他人修改，也不要向生产仓库提交测试条目。

## 新文章与新书的独立流程

公众号原料可保存在本地 `data/公众号/*.md`；按需运行 `python3 scripts/fetch_wx_meta.py` 生成公开文章数据，先检查输入和输出。已知标题/链接时也可直接维护 `articles.json`。

豆瓣与读书记录脚本会抓取数据、下载模型或重建星图，**不是前端构建必需步骤**。`scripts/embed_map.py` 读取 `corpus/books_raw.json`，合并本地读书记录与 inbox，输出 `web/public/data/graph.json`。运行前备份公开数据、确认 Python 环境及依赖；脚本仍有固定 `~/Desktop/Caelum` 路径，搬迁目录需另行处理。模板见 `corpus/README.md`。

普通网站更新可运行 `bash scripts/update.sh "更新说明"`，它只构建、测试、提交公开网站文件并推送，不重新生成星图，也不读取私人语料。只有明确需要处理新书时，才在完成上述备份和输入检查后，单独运行：

```sh
.venv/bin/python scripts/embed_map.py
```

重建后先检查 `graph.json`、inbox 等输出差异，确认只包含希望公开的内容，再构建和发布。不要用重建星图代替普通网页更新。

## 隐私与备份

`web/public/` 全部公开，不要放私人笔记、口令或截图。`corpus/`、`data/微信读书/`、`data/公众号/` 等原料受 .gitignore 保护，但已经跟踪的文件不受新增忽略规则保护，提交前仍须检查。

阅读标记、领域掌握度、学习笔记、植物记录和住宅札记只属于当前浏览器，清除站点数据、换设备或隐私模式可能使它们不可用。发布不能清空这些键；重要私人内容另行备份，住宅札记可使用页面导出功能保存。
