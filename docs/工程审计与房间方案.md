# Caelum：工程审计与房间方案

审计日期：2026-10-20（新加坡时间）。本文记录修改前证据、方案选择与维护边界；最终实测结果由本次交付记录补充，不能把计划等同于测试通过。

## 1. 现有架构与数据流

仓库远程是 `nyxbyb/nyxbyb.github.io`，已是 GitHub Pages 用户站点仓库；`/web/` 是当前保留的应用目录，并非另一个名为 web 的项目仓库。修改前页面主体是约 2,650 行的原生 HTML/CSS/JavaScript；Vite 5 构建它，Svelte 5 插件存在于配置，但没有 Svelte 组件。此前曾按用户授权实现 Three.js 室内；用户进一步要求提高美感并改用二维住宅设计册后，当前入口采用原生 HTML/CSS/JavaScript、SVG 平面和概念影像，不加载 Three.js。

| 层 | 真实文件与职责 |
| --- | --- |
| 主页面 | `web/index.html`：六个滚动章节、Canvas 星图、沉浸式星图、星域下钻、推荐、设置和在线编辑；科研保留在计算机分支 |
| 星图交互 | `web/starmap/interaction.js` 与 `interaction.css`：输入手势、书名/作者搜索、选择反馈、键盘和移动面板；通过适配接口使用既有图数据和相机 |
| 历史副本 | `caelum.html`：早期维护副本，不能再覆盖修复后的主页 |
| 公开内容 | `web/public/data/graph.json` 书目与三维坐标；`articles.json` 已公开文章；`text.json` 双语文案；`inbox.json` 待处理条目；`house.json` 双语住宅程序；`room.json` 六类日常内容；`web/public/tree.json` 三个活跃星域；`domains-archive.json` 原四域完整归档 |
| 本地原料 | `corpus/`、`data/` 与 `scripts/`：豆瓣/公众号/读书记录抓取、文本嵌入、降维；包含私人材料，独立于前端构建 |
| 本地状态 | `caelum_*` 浏览器存储：主题、语言、书目三态标记、领域掌握度与个人笔记；不代表跨设备备份 |
| 未来的家 | `web/room.html` + `web/room/room.js`、`room.css`：二维设计册的空间切换、影像、设计文字、来源、札记与导出；`house-plan.js` 生成九区原生 SVG 平面，`navigation.css` 维护空间导航 |
| 日常内容 | `web/room/daily-life.js` 与 `helpers.js`：保留书架、茶、声音、植物、时间、暖光六类内容，读取 `room.json` 及现有书目；不依赖三维命中 |
| 历史三维源文件 | `web/room/world.js`、Three.js 依赖及相应历史测试保留；当前房间入口不导入它们，也不加载三维运行资源 |
| 构建部署 | Vite 多页面构建 → `web/scripts/package-pages.mjs` → `web/dist/`；只发布公开产物 |

过去同时有根目录跳转页、两个 HTML 副本、三条 Pages 工作流以及文档副本。此处最需要明确的是唯一来源与发布边界，而非引入更大的组件框架。主页的全局函数和大文件仍是维护成本；本次保留其接口，新功能独立，不做无关大重构。

## 2. 修改前已确认的问题

### 线上复现（浏览器，1280 × 720）

实际访问 `https://nyxbyb.github.io/web/`，首页个人信息与研究链接出现，但控制台在初始化阶段记录：

- `TypeError: Cannot read properties of null (reading 'classList')`，`immIdleLoop`，线上第 1789 行。动画循环在后置面板 DOM 可用前访问元素。
- `TypeError: Cannot read properties of undefined (reading 'zh')`，`openLeafPage` → `renderDomains` → `loadTree`，线上第 1580 行。目录数据实际是 `{ domains: [...] }`，渲染入口不能直接假定它是数组。
- 该次会话中星域没有列出四域，星屑停留于“待接入文章…”，多处文案为空。这些是上述异常会话的可见结果，不能据此断言内容已经丢失。
- 独立 HTTP 检查确认 `/`、`/web/`、`/web/index.html` 均为 200，但 `/web/data/graph.json`、`/data/graph.json`、`/web/data/text.json` 和 `/web/docs/更新指南.md` 是 404；数据实际在 `/web/public/data/graph.json` 可读，根手册 `/docs/更新指南.md` 可读。线上 `/web/` 的 HTML 哈希与历史 `caelum.html` 一致，表明当时发布的是源码目录结构，而非预期 Vite 产物。修复必须同时解决初始化和部署路径。

### 代码与配置直接确认

| 事实 | 影响与修复方向 |
| --- | --- |
| `deploy.yml`、`jekyll-gh-pages.yml`、`static.yml` 均监听 main 并争用 Pages | 三种产物来源冲突；其中静态流程上传整个仓库。收敛为一条仅发布构建产物的工作流。未把未查到的历史失败归因为此。 |
| 旧 Vite base 为 `/`，Vite 工作流上传 `web/dist` 根，而根跳转和当前分享地址要求 `/web/` | 保留路径必须让产物真正含 `web/index.html`，不是只改变 canonical。 |
| 在线编辑 API 使用 `data/text.json`、`data/inbox.json`，源文件在 `web/public/data/` | 发布文件路径与仓库源文件路径不同；写入必须指向源文件。 |
| token/管理口令写入 localStorage，公开前端校验管理口令 | 同源脚本可读取持久凭证；公开口令校验不能提供服务器访问控制。改为本次请求使用 token，并以 GitHub 权限为准。 |
| 多处外部内容直接进入 `innerHTML` 或内联事件字符串 | 存在注入面，属于代码层面风险；没有证据表明已经遭到利用。为文本和 URL 提供各自的安全处理。 |
| `scripts/update.sh` 自动把 `caelum.html` 覆盖至 `web/index.html`，然后 `git add -A`、commit、push | 会丢失对新主页的修复并可能过量暂存。废止旧复制约定，部署前明确验证与检查暂存范围。 |

私人读书标记、笔记与原始语料不应被清空或重新生成。未用真实生产 token 做写入测试，未主动轮换凭证，未发布测试文章；token 是否曾被第三方读取无法由静态审计判断。

## 3. URL 决策

| 方案 | 成本、兼容性与风险 | 本次决定 |
| --- | --- | --- |
| `https://nyxbyb.github.io/web/` | 最低变更；浏览器自然提供 index 文档，`/web/index.html` 同时可用；相对数据与手册链接稳定 | 作为规范分享链接，保留原链接；根目录跳到 `/web/` 并保留 query/hash |
| `https://nyxbyb.github.io/` 直接承载主页 | 仓库名称已符合用户站点要求，无需改名。但需要统一资源 base、旧 `/web/` 跳转和手册位置，并检查搜索收录与所有内链 | 暂保留根目录兼容跳转，不为省略四个字符改变所有内容路径 |
| 独立域名 | 增加购买续费、DNS、域名验证、HTTPS 与链接迁移维护；需用户选定和拥有域名 | 适合品牌稳定后实施，本次不购置域名、不改 DNS |

GitHub 官方说明用户站点默认使用账户根域名；项目站点才默认带仓库名。[站点类型](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。Vite 要求 base 对应实际公开路径，[静态部署文档](https://vite.dev/guide/static-deploy.html#github-pages)。域名方案应先验证所有权，再配置 DNS；[GitHub 域名文档](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/about-custom-domains-and-github-pages)。

## 4. Coding Agent 工程实践

实际阅读 [AGENTS.md 官方约定](https://agents.md/)、[Codex 项目指令文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)与 [GitHub Copilot 仓库指令](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/add-custom-instructions/add-repository-instructions)。共通点是保存真实命令、架构入口、安全边界与验证方式，让后续修改减少重复探索。Codex 的目录指令按根到叶叠加；不能假设所有 Agent 都有完全相同的发现规则。

本仓库采用一份简短 `AGENTS.md`，把长期约定与本次审计分开。它不复制通用开发模板、不要求每次小编辑重读全仓、不增加一套多文件任务框架。重要上下文是“web/index.html 才是源”“只发布 dist”“不得清空私人存储”“build 后 test”和“浏览器实测与静态检查分别报告”。官方也建议及时修剪膨胀指令、按任务读取上下文：[OpenAI 工程指引](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)。

执行采用 A 审计与选型 → B 修复真实初始化/部署/安全问题 → C 独立房间 MVP → D 无障碍与视觉整合 → E 构建和浏览器回归。测试聚焦数据形状、路径兼容、初始化及交互行为；不用与实现逐字相同的断言代替实际观察。

## 6. 技术选择：二维住宅设计册

第一轮以原生 SVG 2.5D 完成基础房间和内容联动，此后按用户明确授权实现 Three.js 室内。2026-10-20 用户再次调整方向：认为实时三维难以达到所需美感，要求尝试二维、参考专业建筑作品，并扩展为未来建房或装修可继续使用的整屋素材。当前方案据此改为二维设计册；此前的三维授权不意味着入口必须继续运行三维场景。

| 方案 | 能力与代价 | 当前用途 |
| --- | --- | --- |
| 原生 SVG 平面 | 可表达房间关系、概念尺度、家具和选区，并提供键盘入口 | `house-plan.js` 生成九个可选区域；不用位图冒充可校核平面 |
| JPEG 概念影像 | 表达光、材质与氛围；不能证明与平面精确对应或构造可建 | 既有起居影像与五张新增空间影像；没有配图的区域继续展示平面 |
| 双语公开 JSON | 内容、面积、概念尺寸与落地提示独立维护 | `house.json` 维护住宅程序，`room.json` 维护日常内容 |
| 原有 Canvas | 适合既有书目投影和星图；交互语义由 DOM 提供 | 保留主页星图，仅将输入与可访问面板拆入独立模块 |
| CSS 与浏览器原生 API | 支持短状态过渡、焦点、音频、全屏等界面行为 | 不为简单过渡增加 GSAP、React 或额外模型依赖 |
| 历史 Three.js 模块 | 记录此前室内实现，依赖仍锁定 `0.186.1` | `world.js` 与相应测试保留，但不在当前房间入口加载 |

模块边界是 `room.js` 管九区选择、影像、公开设计文字、设计来源、每区札记和 Markdown 导出；`house-plan.js` 管 SVG 平面的绘制与选择；`daily-life.js` 管保留的六类日常交互。住宅程序以约 200㎡概念建面为工作模型：166㎡净功能与 34㎡墙体、结构、机电预留，30㎡庭院另列。四个可关门的房间是主卧、书房、客房兼多用房与未来预留房，并非四间卧室。面积、几何与原创参考依据见[未来住宅设计简报](未来住宅设计简报.md)，公开副本位于 `web/public/docs/未来住宅设计简报.md`。

札记只写入当前浏览器的 `caelum_house_notes_v1`，不写公开 JSON，也不自动上传仓库。导出包含整屋设计说明与当前札记；完整简报另有阅读、下载入口。存储不可用时应保留编辑和导出，并反馈保存失败，不清空既有 `caelum_*` 记录。

当前 `room.js` 导入 `assets/interior-dusk.jpg` 与 `assets/house/{study,bedroom,kitchen,bath,flex}.jpg`。PNG 为生成原稿，旧 `scene.svg` 与 `world.js` 留作历史源文件；入口不加载旧三维场景。影像是原创生成概念图，不是实拍、建成效果或施工依据；完整提示词和来源见《房间视觉素材》。设计来源弹窗链接 Aalto House、Pawson Philippines House、Norm Forest Retreat、Kuma Wood / Peel 四项官方案例，仅进行原则转译，不复制其图纸和摄影，不暗示原作者参与本住宅。

## 7. 信息架构与房间体验

## 8. 验证与尚需区分的风险

`npm --prefix web run build` 生成完整 Pages 目录，`npm --prefix web test` 检查严格静态服务器上的 `/web/`、旧链接、资源与公开数据；浏览器另查主页面和房间的真实交互。测试时不使用生产 token，不删除原始数据，不运行嵌入流程重建书目。

线上原版浏览器错误、六仓库调研和此前版本的验证属于历史记录。当前二维设计册需对集成产物重新 build、test，并检查九区导航和平面、影像切换、三类详情、双语、来源、札记保存与导出、六类日常内容、窄屏、减少动态效果、存储不可用与资源失败。当前文档更新不代表这些浏览器检查已经完成；实际结果由主任务更新《验证记录》。旧截图、旧通过数量不能代表本轮验证完成。自动测试通过不能代表真实远程提交成功，预览成功不能代表 main 已发布。

保留的长期限制：浏览器存储不是备份；纯静态在线编辑仍需站点所有者提供仓库权限；相同 origin 上可信脚本可接触输入中的 token；主页大文件仍有耦合；原料抓取/模型嵌入属于独立维护工作。独立域名仍是后续可选项；二维住宅是可持续完善的设计研究，不能代替结合真实项目的建筑与施工设计。上线状态须在实际部署和线上检查后另行记录。
