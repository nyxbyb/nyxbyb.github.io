首次三维检查发现 Three.js 已移除 PCFSoftShadowMap 的警告，已改用当前 PCFShadowMap；后续构建和会话再次核对。房间渲染包约619kB（gzip约160kB）按需加载，不进入主页；Vite 会提示单包超过500kB。静态占位使用622KiB JPEG，原始PNG保留为设计素材，未打入发布产物。

## 上一轮验证限制（最新范围见本轮集成验证）

- 未使用真实 token 公开写入测试内容；没有测试 token 的跨权限/过期矩阵。网页添加是待处理 inbox，仍需整理或单独嵌入，提交后不会立即变成星图坐标。
- 未在实体 iPhone/Android、Safari/Firefox 上执行跨浏览器矩阵；AbortController 等兼容处理有代码与自动检查，不能冒称这些设备已实测。
- `prefers-reduced-motion` 样式、后台暂停、数据失败重试与静态 SVG 基础展示已实现；本次浏览器没有逐项模拟禁用 JS、网络断开、存储受限与 OS 减少动态效果设置。
- 上一轮没有 WebGL 依赖；本轮 Three.js 接入后必须新增 GPU 不可用、加载失败、上下文丢失与资源释放检查。未运行 Lighthouse、弱网、帧率、电池或长时间内存压力基准，不给出没有测量依据的性能分数。
- 本机笔记不是云备份。线上发布状态必须在推送与 Actions 成功之后另行确认；本记录的本地通过不代替远程发布检查。


## 正式发布核查（2026-10-20）

此前工作曾停在本地验证，未推送；用户看到旧站符合线上状态。此次将已验证改动提交为 `eb39c16` 并推送 main，[正式工作流 39361916954](https://github.com/nyxbyb/nyxbyb.github.io/actions/runs/39361916954) 构建、24 项回归和部署全部成功。然而同一提交的 GitHub 自动 `pages build and deployment` 在其后完成，线上 `room.html` 又出现未构建的 `./room/room.js` 引用，确认存在实际覆盖，不能据单个绿灯宣布站点正确。

正确长期配置是 Pages Source = GitHub Actions。当前浏览器未登录仓库设置，GitHub 连接器重跑任务返回权限不足；没有索取、保存或扩大凭证权限。曾尝试通过公开 API 等待旧流程完成（49f5c00），但 GitHub runner 的请求返回 HTTP 403，工作流按预期停止，没有跳过验证或扩大权限。用户随后明确确认已将 Source 切换为 GitHub Actions。最终实现改用现有 Pages 权限核验 workflow 来源，避免依赖未认证的公开 Actions API；最终状态仍需结合产物引用、数据地址和真实页面再次核对。
